# 開始時の「1」停止・点滅修正 v28

## 再現した原因

v27では、カウント後の最初の動画時刻が開始位置から0.25秒以内であることを要求していました。最初の通知が0.32秒だった場合、動画は進んでも譜面は「1」に残りました。一度だけの巻き戻しも失敗すると、その状態を抜けられません。修正前のクライアントテストで `countdown` のままとなる失敗を記録しています。

読み込み状態になると準備済みのノーツまで隠すため、状態の揺れがノーツの消失・再表示になります。また、同じ寸法でもCanvasのwidth/heightを設定しており、ResizeObserverの重複通知で描画済みの画像を消去していました。

## 変更

- 時刻通知の遅れを経過時間に応じて最大0.75秒まで受け付けます。ただし最初の未処理ノーツを越えた通知や大きなシークは受け付けません。
- 1.5秒以上開始を確認できない場合は「1」を出し続けず、読み込み表示で待ちます。新しい再生時間の前進を確認し、開始位置への巻き戻しが完了してから再度準備します。自動復旧が繰り返し失敗した場合はEnterで再開できる画面を出します。
- 動画URLのIDと大まかな動画長を確認し、選択MVと明らかに異なる情報では譜面を開始しません。期待する情報が戻った時点で一時停止されている場合も、再生を一度依頼して復帰できます。PLAYING通知が欠けても状態の取得で復帰します。
- 初回準備後の読み込み中は、ノーツを消さず同じ位置に保ちます。変更のないCanvasサイズ、カウント文字、案内文を繰り返し書き換えません。未入力の鍵盤を開始直後だけ光らせる初期値も修正しました。
- 選曲時に作った譜面を再利用し、開始時の重複計算を省きます。ピアノの音高付与とプレイ状態はコピーに対して行います。

## 検証

`npm test` は88件成功。クライアントのYouTube模擬プレイヤーで、最初の時刻通知の遅延、90秒間の停止・異なる動画情報、広告明けに相当する情報の復帰、一時停止状態での復帰、失敗する巻き戻し、欠けたPLAYING通知を確認しました。待機中に判定・ミス・譜面の時刻が先行しません。描画関数を通した検査では、読み込み中もノーツの位置と個数が維持され、寸法が変わらないリサイズ通知ではCanvasを消去しません。

全35曲・105譜面の開始用データは修正前と同一です。ローカルNodeの比較では、譜面構築とピアノ音高付与にかかった合計が約2451msから92ms、1譜面の最大が約111msから4msに減りました。選曲時の計算を再利用する部分の比較であり、ブラウザのフレーム時間を測定した値ではありません。

v28の初回公開時点では実ブラウザでの広告再生は未検証でした。その後、実際の広告を含む検証と追加修正を行い、[v29の検証記録](startup-v29.md)にまとめました。[YouTube IFrame Player API](https://developers.google.com/youtube/iframe_api_reference)には広告の開始・終了を示す公開イベントがなく、動画情報と時刻の確認による対処です。広告中もMVと同じ情報・時刻が返る場合は完全に判別できません。

譜面・採点版は `piano8-hands-v19` を維持し、バックエンドは変更しません。
