# カウント後の停止・再カウント修正 v23

「3・2・1」の後、動画がまだ開始していないのに読み込み画面へ戻り、短い停止の後にも巻き戻しとカウントを繰り返すケースを再現して修正しました。

## 変更

- カウント終了の120ms前に非同期の再生開始を依頼し、動画の時刻が実際に前進した最初のフレームで音と譜面を開始します。PLAYING通知だけで時刻が0のままなら、最後の「1」を維持します。
- カウント前に巻き戻しの完了を確認します。冒頭では0秒から40ms以内の位置で停止していることを確認してからカウントを始めます。
- 巻き戻し前の古い時刻が届いた場合は一度だけ開始位置を修復し、表示中のカウントを最初に戻しません。
- 開始後の読み込み待ちが1.5秒未満なら、最初の新しい動画フレームでそのまま復帰します。再度の巻き戻し・3秒カウント・無音の0.35秒確認は行いません。
- 長い読み込み待ちでは、再び準備を確認してからカウントします。自動再生が拒否された場合はEnterで再開できる画面に戻します。

## 検証

修正前は、再生開始が遅れるテストでカウント終了直後の状態が `loading` になり、失敗することを確認しました。修正後は以下を検証しています。

1. 動画再生が300ms遅れても、読み込み画面への逆戻りや判定の先行がない。
2. PLAYING通知が先に届き、動画の時刻が0秒のままでも、判定を開始しない。
3. 最初の0.02秒の実動画フレームから発音・判定を開始する。
4. 600msの短い停止後は0.07秒の最初のフレームで音を戻し、再カウントや追加シークを行わない。
5. 遅いシークと古い2秒の時刻を受けても、表示中のカウントをやり直さず一度だけ復旧する。
6. 3秒の長い停止では、判定を止めたまま新しいカウントを用意する。
7. 最後の再生切り替えで自動再生が拒否されても、再開画面を操作できる。

YouTubeプレイヤーの遅延・通知順序を模擬したクライアントテストによる検証です。`npm test` は85件成功し、全105譜面の入力再生・発音・長押し・FLOATも通っています。譜面と採点バージョンは引き続き `piano8-hands-v19` を使用します。
