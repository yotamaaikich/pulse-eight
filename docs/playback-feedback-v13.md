# 開始時の助走・打鍵音・入力時刻の修正 v13

全35曲・105譜面に共通するクライアント側の修正です。譜面バージョンはpiano8-arrangement-v12を維持します。

## 開始前のノーツ

動画の読み込み・冒頭広告の待機中はノーツを表示せず、再生位置が落ち着いてからカウントダウンを開始します。その間は音楽を0秒（再開では停止位置）に止めたまま、表示上の譜面時計だけを負の助走時刻から進めます。最初のノーツが必ずレーンの奥から現れ、譜面時計が曲の再生位置に達した時点で動画の再生を要求します。通常3秒、遅いスクロールで移動時間が足りない場合は助走を延ばします。低速の追加助走はREADY表示、最後の3秒は3・2・1です。

全画面を含め、カウントダウンの背景を透明にして先に流れてくるノーツを見られるようにしました。判定・スコア・長押し処理は音楽が再開するまで進めません。速度0.5〜2.0倍、判定補正±500msで、全105譜面の最初のノーツが最初から途中に置かれないことを検査しています。広告後の再生確認・非同期シークの待機・二重カウントダウンの回避も保持しています。

## ピアノの発音漏れ

通常、ロング、FLOATの最初のレーンキー入力でピアノを1回鳴らし、FLOAT成功時は別の短いきらめき音を重ねます。音程データのないノーツと空打ちは、長い固定音程を足す代わりに、短い実録ピアノの打鍵成分を鳴らします。全35曲で有効です。確かな音程データのあるノーツのピアノ音高・音色は引き継ぎます。

代替打鍵音はフィルタとゲインを調整し、密集した音の余韻が残っているだけで全体音量が大きく下がらないようにしました。6つのサンプルのうち一部が読めない場合も、読めたサンプルを音高変換して発音し、未読込のものだけ再取得します。読み込み待ちのキー入力を遅れて鳴らすキューは作りません。キー解放やホールドのコンボ加算では再発音しません。

## 全35曲の時刻照合

同じ公式音源であることをSHA-256で検証し、全35曲・合計46844個のアタック候補を別の測定方法で照合しました。旧解析の約93msの周波数窓に対し、約23msの短い周波数窓と、時間領域の約8msの振幅包絡を約2ms刻みで比較しています。強い2つの立ち上がりが近い時刻に現れ、競合する候補がないことを条件に補正候補を分類しています。既知の開始時刻で作った検証用の音と無音も使用しました。

この判定は音楽的に正しい採譜である保証ではありません。歌と楽器の重なりや、なだらかな音では位置が曖昧です。ユーザーから現在の譜面がおおむね合っているとの評価を受けたため、候補を一括で譜面へ適用していません。下表は監査結果であり、変更済みノーツの数ではありません。実装側では、打鍵時に動画の再生時刻を取り直し、前の描画フレームの時計による遅れを除きます。巻き戻し・シーク・バッファリングの時刻は受け入れません。
